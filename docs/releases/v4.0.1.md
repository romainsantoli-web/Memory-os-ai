## Contenu et compatibilité

Distribution `memory-os-ai`, licence **LGPL-3.0-or-later**, Python ≥ 3.11. Les deux
licences et les deux moteurs sont embarqués. Entrées installées :

| Commande | Cible |
|---|---|
| `memory-os-ai` | `memory_os_v4.server:run` |
| `memory-os-v4` | `memory_os_v4.server:run` |
| `memory-os-ai-v3` | `memory_os_ai.server:run` |
| `memory-os-relay` | `memory_os_v4.ops.relay:main` |
| `memory-os-admin` | `memory_os_v4.ops.cli:main` |

`memory-os-ai[ops]` ajoute cryptography ; le moteur standard n'exige pas cet extra
pour démarrer. Les notices sont installées sous
`<venv>/share/doc/memory-os-ai/` (docs v4 dans son sous-dossier `v4`).

Voir [CHANGELOG](../../CHANGELOG.md) pour SEC-1, dédup/supersession, douze réparations,
reçus JSONL et SQLite S1. Magasin JSONL existant : aucune migration automatique.
SQLite S1 reste exclusivement expérimental/neuf ; l'ALPHA industrielle attend
S2–S5. Les embeddings réels sont nécessaires à la recherche sémantique ; le mode
hash des smoke tests qualifie démarrage/contrat, pas la pertinence du rappel.

Le dossier local `.local-qualification/release-4.0.1/` contient les journaux,
environnements et provenance (sans secret), deux artefacts, empreintes SHA-256,
manifeste et procédure de publication gardée par un refus tant que `release_ready`
est faux. Les environnements d'installation sont hors checkout, séparés pour wheel

autorisée pendant les smoke tests. Les commandes sont exercées réellement sur
données synthétiques ; tout TCP interdit dans le sandbox est marqué non exécuté.

projet selon CI, wheel/sdist, `twine check --strict`, `pip check`, cinq entry points.

launchd doivent être prouvées hors sandbox sur la **révision finale** après corrections.
